# Open Fit — Comprehensive Engineering Audit

## Executive Summary

Open Fit is a self-hosted fitness/wellness platform built on a Rust workspace backend, a React/TypeScript frontend that currently carries **two parallel UI trees** (a deprecated `screens/` tree and the canonical `design/` redesign), and an Android native device layer that speaks standard GATT plus two proprietary protocols (Huami/Zepp and Garmin). The codebase is fundamentally sound: the WASM compute-plugin sandbox is strict and correct, the database layer uses chunked writes and bounded queries in the hot paths, and the incremental analytics worker is well-designed. The most impactful problems are **architectural rather than functional** — there is no device-protocol abstraction (every new device touches ~9 files), the built-in computed-metric registry is hand-maintained in a way that lets new metrics silently fail to register, ~10.8K lines of dead legacy UI still ship, and several concrete resource leaks exist (an unclosed WebSocket and two never-shutdown Android executors). None of these block current functionality, but they compound friction and risk as the device/metric roster grows.

### Top priorities

- **Close the leaking WebSocket in `useAnalyticsStatus`** — a genuine, accumulating resource leak with a ~5-line fix (frontend memory).
- **Shut down the two Android `ExecutorService` instances on plugin destroy** — background threads pin `Context`/`File`/plugin state indefinitely (android memory).
- **Make the built-in algorithm registry compile-time-safe or auto-discovered** — today a forgotten `vec![]` entry (or a test count bump from 5→6) silently disables a metric (plugin extensibility).
- **Introduce a `DeviceProtocol` interface in the Android BLE layer** — collapses adding a device from ~9 files to ~3 and removes the god-file string dispatch (device extensibility).
- **Cache the `PluginHost` in `AppState`** instead of reloading every WASM module from disk on every analytics request (backend memory).
- **Delete the dead `web/src/screens/` tree (~10.8K LOC)** now that the redesign is canonical and fully wired (frontend duplication).
- **Detect device protocol from advertised BLE services, not device-name regexes** — current heuristics misclassify devices (device extensibility).
- **Split `BleProvider` into connection vs. live contexts** to stop a re-render storm at BLE streaming frequency (frontend perf).

## Architecture Overview

**Backend (Rust workspace, `crates/`).** `ofit-core` holds domain types, the `Algorithm`/`RunnableAlgorithm` traits, `AlgorithmSpec`, dedup/source-resolution logic, and `DerivedMetric`/`DerivedStream`. `ofit-analytics` implements the five built-in algorithms (TrainingLoad, TrainingEffect, Readiness, Sleep, AnomalyFlag) plus the parameter registry. `ofit-plugins` is the sandboxed WASM host (extism). `ofit-ingest` parses FIT/GPX/TCX/Zepp/Garmin and runs the import pipeline. `ofit-db` is the sqlx data layer (one large `lib.rs`). `ofit-api` is the axum surface: handlers, analytics orchestration, auth, and the incremental worker.

**Frontend (`web/src/`).** Two parallel screen trees exist. The legacy `screens/*` tree is dead code, unreferenced by routing. The redesign `design/pages/*` (mobile) + `design/desktop/*` (desktop) is canonical, fully wired through `design/wiring.ts` (1,074 LOC of view-model hooks). Two BLE providers exist: `ble/BleProvider.tsx` (standard Web Bluetooth GATT) and `ble/native/NativeBleProvider.tsx` (Capacitor native bridge).

**Native device layer (`mobile/android/.../org/openfit/app/`).** `OpenFitBlePlugin.java` (1,121 lines) is a god-file mixing standard GATT, Huami, and Garmin dispatch. `BleForegroundService.java` keeps BLE alive; `RecordingService.java`/`RecordingPlugin.java` handle workout recording; `FitEncoder.java` re-implements the FIT codec in Java. Protocol logic lives in `huami/*` and `garmin/*` as standalone session classes — cleanly separated but wired in only via string type checks.

## Compute-Plugin Isolation & Extensibility

**Isolation is excellent. Extensibility has substantial, mostly silent-failure-prone friction.**

### Isolation (verified clean)

The WASM sandbox (`crates/ofit-plugins/src/sandbox.rs:62-101`) is deny-by-default: no ambient capabilities, no network (empty allow-list + `disallow_all_hosts`), no filesystem (`with_wasi=false`, no preopens), no host functions, bounded memory/CPU with timeout interrupts. A **fresh instance per call** (`host.rs:128-154`) prevents state leakage, and the host overwrites the algorithm id/version/`computed_at` so a plugin cannot spoof provenance. Tests assert the manifest can't loosen policy (`tests/host_unit.rs:88-99`). Built-ins and WASM plugins implement the **same** `RunnableAlgorithm` trait uniformly (`runner.rs:44-59`, `host.rs:215-228`); the API loops generically over the trait and never branches on `AlgorithmKind`. This is the right abstraction. *Recommendation: document the sandbox guarantees in a crate-level/security doc.*

### Walkthrough — adding a new WASM plugin metric (2 files, **no server code edits**)

1. Write the plugin (Rust + extism-pdk, mirror `PluginInput`/`PluginOutput` JSON), compile to `.wasm`.
2. Create `plugins/<id>/plugin.toml` declaring id/version/inputs/outputs and `wasm:{path, sha256}`; drop it next to the `.wasm`.
3. Startup `load_dir_lenient` (`host.rs:259-292`) discovers, validates, loads, and extends the algorithm list. Recompute treats it identically to a built-in.

**How hard is it today?** Plugins are nearly drop-in (the architecture's clear win). Built-ins are not: 5+ files, two of which (the `vec![]` registry and the `pdef!()` plugin-id string) cause **silent failures** when wrong. **The single abstraction that fixes it:** make built-in registration declarative/auto-discovered (macro/inventory or bundled TOML) so the spec, registration, parameter set, and version live in one place per algorithm — eliminating the hand-maintained `vec![]` and the string-keyed param REGISTRY coupling.

## Device Isolation & Extensibility

**There is no unified device abstraction.** Protocol handling is scattered across the web GATT provider, the native god-file, and the standalone session classes, glued together with string literals and name-regex heuristics. Each protocol module (`huami/`, `garmin/`) is internally clean, but they are referenced only through string type checks, never a common interface.

| Severity | Location | What's wrong | Fix |

| **High** | `OpenFitBlePlugin.java:216`, `:880-895` | `deviceType` is a 3-way string (`"huami"`/`"garmin"`/default). `onServicesDiscovered()` dispatches with `if("huami".equals(mode)) setupHuami(g) else if("garmin"...) ...`. ### Walkthrough — adding a new device protocol today (≈9 files, ~15 touch-points)

To add e.g. a Polar H10 with custom crypto:

1. New package `org.openfit.app.mydevice/` with `MyDeviceSession.java` + `MyDeviceSession.Listener` (parallel to `huami/`, `garmin/`).
2. `OpenFitBlePlugin.doConnect()` — add a `"mydevice"` mode string check (`:216`).
3. `onServicesDiscovered()` — add `else if("mydevice".equals(mode)) setupMyDevice(g)` (`:880-895`).
4. `onMtuChanged()` — add `else if("mydevice"...) startMyDeviceSession(g,mtu)` (`:891-895`).
5. `DeviceLink` — add a `MyDeviceSession` field + listener impl (`:610-627`, `:1030-1088`).
6. `onCharacteristicChanged()` — wire its characteristic UUIDs (`:913-928`).
7. `NativeBleProvider.tsx` — add `"mydevice"` to the `SavedDevice` union (`:28`), dispatch cases in `open()` (`:113-118`) and `addAndConnect()` (`:216-221`).
8. `BleDevices.tsx` — add `isMyDevice()` heuristic (`:117-118`) and a UI button (`:338-356`).
9. `RecordingService.java` — HR is already wired; cadence/power need new `feed*` statics + wiring in `emitSample()` (`:320-331`).

**How hard is it today?** Hard — ~9 files and ~15 edit points spread across Java + TS, with name-regex classification that can misroute devices. **The single abstraction that fixes it:** a `DeviceProtocol` interface plus a `ProtocolRegistry` (Android) and service-based protocol inference (web). With those, a new device becomes ~3 files: implement `MyDeviceProtocol`, register it (`addProtocol("mydevice", MyDeviceProtocol.class)`), and update one inference rule — a true drop-in. A shared `DeviceIdentity` in `ofit-core` additionally unifies live streaming with file import so one physical device is one entity everywhere.
